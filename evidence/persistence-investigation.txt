Per-instance spring tuning persistence investigation
2026-11-01. Read-only game analysis; generated wrappers establish signatures, native disassembly establishes behavior.

Sources: BepInEx/interop/Assembly-CSharp.dll (ILSpy output evidence/interop/Vehicle.cs, Save.cs, MemBuf.cs, VehicleEditor.cs), GameAssembly.dll, evidence/mfl_metadata.py and mfl_pe.py. Addresses below are PE virtual addresses, image base 0x180000000. Interop bodies are invocation wrappers, not original C#.

Vehicle.Node has no string/JSON extension field. It has partId, color, attachAngleIndex, attachmentIndex, bindingOverrides, autoReturnOrNoSuspension, controlGroup, children, parent, parentChildIndex, editorPosition/Rotation and runtime references. Runtime part/go references are unsuitable persistent identity. Node carries SerializableAttribute.

Binary wire format v5
WriteNodeBinary(MemBuf buf) at 0x18047e5d0 writes partId UShort, color byte, angle byte, attachment byte; each bindingOverride uses two bytes (binding enum, inverted flag). There is NO binding count: reader infers count from PartSO.actions. Therefore adding fake binding data corrupts alignment. Next byte combines controlGroup low7 and autoReturnOrNoSuspension highbit. Then nonnull child count byte; each child is slot index byte + recursively encoded Node. Children array preserves attachment slots rather than being compacted. ReadNodeBinary_v5 at 0x1804802b0. No field can safely hold seven tuning floats.

Recommended save patch pair
1. Vehicle.Node.WriteVehicleSave(MemBuf buf, string name), instance void, native 0x18047e290 / token0x6000eff: postfix append bounded extension bytes with buf.WriteBytes(Il2CppStructArray<byte> bytes, int l, int offset=0). Native writes UShort5 then WriteNodeBinary; if name != null, writes UInt0xffffffff then WriteString(name).
2. Vehicle.Node.ToBase64(), instance string, 0x1804809b0 / token0x6000f0b: postfix decode __result, append same extension, encode. It DOES NOT call WriteVehicleSave: clears static tmpBuf len/pos; writes UShort5 and WriteNodeBinary; base64 encodes bytes[0:len]. This independent patch is essential. Game.GenerateSaveState at0x180331380 calls ToBase64 at0x180331425; Save.State.vehicleBase64 stores result.
3. Vehicle.Node.ReadSavedVehicle(MemBuf buf, out string name), static Node, 0x18047e310 / token0x6000f00: postfix decode extension into returned root. Native reads version then calls matching _v0.._v5. It optionally reads ONE UInt if pos<len; if UInt==0xffffffff then reads name string. It does not require end-of-buffer and ignores remaining bytes. IMPORTANT: without a name, this probe consumes the first FOUR extension bytes. Decoder must account for current pos OR pos-4, or use footer-at-end framing and validate payload start against native consumed position. A magic+length+payload+footer scheme avoids scanning arbitrary native bytes. A malformed/unknown extension must leave native vehicle valid, ignored/logged.
4. Vehicle.Node.FromBase64(string base64), static Node, 0x180480ab0 / token0x6000f0c: native decodes into tmpBuf, resets pos0, and calls ReadSavedVehicle (call0x180480c45), so #3 covers it, no separate patch needed.

MemBuf fields: bytes Il2CppStructArray<byte> at0x10; len int0x18; capacity int0x1c; pos int0x20. Native ToBase64/FromBase64 uses growable buffer, not a fixed small vehicle size. No explicit maximum vehicle size or full-input-consumption validation observed in these Node save/read methods. This is NOT proof every upload/storage path has no limit. Bound extension payload, node count, depth and finite tuning values independently. Copy only bytes up to len, not capacity. Preserve preexisting name exactly.

Extension identity recommendation
Stable preorder traversal with ascending child slot, node partId validation, total node count and topology hash (partId + child slot structure). Do not use native pointers in on-disk data. Store only tuned nodes, seven finite float values, version, and tree signature; reject mismatched topology atomically rather than partially applying tuning to another spring. For copying compare source/destination child slots/partId recursively and clone tuning values rather than sharing mutable setting objects.

Copy/duplicate patch pairs
Vehicle.Node.Copy(), instance Node,0x1804808b0/token0x6000f0a clears tmpBuf, directly calls WriteNodeBinary then ReadNodeBinary_v5, bypasses all wrappers above. Postfix recursive slot-correspondence copy of tuning from __instance to __result required.
Vehicle.Node.CloneNoChildren(), instance Node,0x180480e80/token0x6000f0f allocates Node; copies ordinary settings and binding array; allocates empty children array matching source size and copies editor transform/attachmentPoints. Postfix copy just source node tuning required. This supports piecewise paste construction. VehicleEditor.BuildPasteTree / BuildPasteTree2 are available wrapper methods; broader clipboard paths still need runtime validation.

Undo/redo: IMPORTANT extra path, not covered by save or Copy hooks
VehicleEditor.PushUndoStack(), instance void at0x180461080, serializes vehicleTree to a MemoryStream via native0x18103b340 (BinaryFormatter-style serialization); no ToBase64 or Node.Copy invocation. undoStack is List<Il2CppSystem.IO.MemoryStream> at0x438, undoStackPos int0x440, undoStackSize int0x444. Limit100.
Push: size=pos; if pos==100 removes first stream, appends it, decrements pos and size; clears selected stream then serializes current tree; sets size=pos=oldSize+1. Postfix can associate immutable tuning snapshot with stream undoStack[undoStackPos-1]. Empty snapshots must overwrite old values too. Guard bounds and retain a bounded set; do not keep unmanaged pointer keys forever across editor recreation.
VehicleEditor.PushUndoStackCopier(Game g), instance void0x180461010 temporarily replaces editor.vehicleTree with player vehicle root.Copy(), calls PushUndoStack, then restores original editor root. Copy hook + PushUndoStack postfix works for this path.
VehicleEditor.Undo(Game g), instance void0x180461290: if pos>0 serializes current tree to NEW MemoryStream (native0x18042c1a0), deserializes undoStack[pos-1], calls ResetVehicle, replaces undoStack[pos-1] with serialized old/current tree stream, then decrements pos. It SWAPS snapshots; a dictionary keyed old stream alone is insufficient without recording replacement stream.
VehicleEditor.Redo(Game g), instance void0x180461460: if pos<size serializes current tree to NEW stream, increments pos, deserializes undoStack[oldPos], calls ResetVehicle, replaces that same slot with old/current tree stream. Snapshot swap likewise required.
VehicleEditor.ResetVehicle(Game g, Vehicle.Node veh), instance void0x180461630: copies input veh via Node.Copy at0x180461703 and installs editor.vehicleTree, rebuilding previews.
Recommended undo hooks: Undo/Redo prefix determine target index (Undo pos-1; Redo pos), capture current tuning snapshot and target snapshot; arm per-editor scoped context. ResetVehicle prefix, only within that context, apply target snapshot to veh BEFORE native Copy. Undo/Redo postfix associate previous current snapshot with the replacement stream now at captured index; clear context (including exceptional/finalizer path). PushUndoStack postfix populate newly written stream snapshot. Alternative per-editor indexed snapshot list must exactly mimic rotation, branch truncation and swaps. Native no-op bounds must remain no-op. Menu should call PushUndoStack BEFORE editing (base controls do this).

Limits of static evidence
Native end-to-end live save/load, blueprint load, undo/redo and copy/paste tests still required. A vehicle loaded then saved WITHOUT the mod loses its trailer, as native writer serializes only known fields. Format versions/addresses are build-specific. Topology checks should fail closed after incompatible game updates without obstructing base vehicle load.
