Read-only investigation; no user saves modified.

CONFIRMED TWO FAILURES
1. VehicleEditor.SaveVehicleToSlot bypasses Node.WriteVehicleSave, directly serializing version, WriteNodeBinary, optional name. Existing save hook never executes for this route.
2. PNG transport extracts all transparent pixels, including unused padding, so the reconstructed MemBuf.len is far beyond the true trailer end. Footer-at-buf.len decoder fails even if writer appends trailer correctly.

Recommended patch pair:
- SaveVehicleToSlot prefix capture immutable tuning snapshot of editor.vehicleTree, scope by editor / call; finalizer clear scope.
- ResaveVehicle prefix capture selected SAVED tree tuning from original cached info.buf before native clears it, preserving pos. Existing Node.ReadSavedVehicle decode hook can populate a temporary decoded root; Capture it immediately into pure snapshot. Alternatively scope ReadSavedVehicle observation during native ResaveVehicle, before the known buffer reset.
- WriteVehiclePNG prefix, only within either scoped operation, append captured trailer to info.buf AFTER name has been written and BEFORE PNG encoding. Force append at buf.len (native serialization leaves pos=len but explicit robust). Avoid duplicate append on unrelated PNG updates; preserve native prefix and slot name. Check raw texture capacity before appending; if payload cannot fit do not silently claim saved tuning. Handling oversized payload via another representation would require explicit design.
- Retain existing Node.ReadSavedVehicle postfix but change decoder to recognize a trailer beginning exactly at native consumed endpoint (or endpoint-4 for absent-name marker probe), with bounded forward footer search and digest validation. Allow arbitrary later PNG padding. Do not merely trim trailing zeros: footer/hash can contain zeros and padding can contain old payload/thumbnail data. Search bound MaxPayload+52 from native stream endpoint, candidate footer length/digest/topology must all validate. This also preserves existing footer v1 and regular base64 saves without migration.
- Add tests that model image transport: three-byte padding, arbitrary large zero padding, stale nonzero data after valid footer, checksum-invalid candidate before valid footer, and capacity overflow. Live test must save, load another design, reload saved slot; then restart game to force PNG reconstruction, load again; rename/resave without loading target to ensure unrelated editor tree doesn't contaminate tuning.
